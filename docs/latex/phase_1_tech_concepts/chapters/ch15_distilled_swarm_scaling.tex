\chapter{Deploying the Tier 2 Distilled Swarm: 1,000,000 Agents on Shared MLPs}
\label{ch:distilled_swarm_scaling}

The fundamental bottleneck of financial agent-based simulations has historically resided in the trade-off between cognitive fidelity and computational scale. Chapter \ref{ch:generative_swarms} deconstructed the physical ceiling that prevents online autoregressive Large Language Models (LLMs) from scaling beyond hundreds of concurrent instances. This chapter establishes the engineering foundation of Tier 2: deploying a distilled policy swarm of 1,000,000 concurrent agents executing on host CPU silicon at deterministic, sub-0.2 microsecond latency.

\section{Behavioral Archetype Factorization}

Simulating one million independent neural network parameter sets would overwhelm memory buses and prevent efficient instruction caching. In real-world financial markets, trading entities exhibit clustered microstructural behaviors dictated by mandates, risk constraints, and latency horizons. AMPS exploits this behavioral clustering through \textbf{Behavioral Archetype Factorization}.

Rather than training unique neural networks for each of the 1,000,000 agents, the offline distillation pipeline (detailed in Chapter \ref{ch:mdp_formulation}) trains and freezes compact, two-layer Multi-Layer Perceptrons (MLPs) representing four canonical market participant archetypes:

\begin{enumerate}
    \item \textbf{Market Makers (MM):} High-frequency liquidity providers operating two-sided quote ladders around the mid-price. Their policy balances spread capture against adverse selection risk ($\mu$) and inventory skew penalties ($\gamma \cdot (\text{Inventory}_t)^2$).
    \item \textbf{Institutional Whales (IW):} Capital-intensive liquidity consumers executing programmatic volume-weighted average price (VWAP) or percentage-of-volume (POV) liquidation schedules. Their policies balance market impact against execution urgency.
    \item \textbf{Momentum Scalpers (MS):} Latency-sensitive directional traders exploiting short-term Order Flow Imbalance (OFI) trends and volatility spikes.
    \item \textbf{Noise Traders (NT):} Retail and uncoordinated market participants characterized by stochastic liquidity shocks, loss aversion, and behavioral panic cascades governed by prospect theory \cite{kahneman1979prospect}.
\end{enumerate}

Each archetype policy $\pi_{\theta_k}(a | S_t)$ ($k \in \{\text{MM}, \text{IW}, \text{MS}, \text{NT}\}$) is parameterized by a lightweight 2-layer MLP with a 151-dimensional input layer, a 64-neuron hidden layer with fused ReLU activations, and a discrete action head outputting logits over the action tuple $A_t = (\text{action}_t, \Delta P_t, V_t)$. 

Across all four archetypes, the total parameter count remains under 5 million FP32 parameters ($<5\text{M}$ weights), translating to approximately 20 Megabytes ($\sim 20\text{ MB}$) of uncompressed weight data, or approximately 5.0 Megabytes ($\sim 5\text{ MB}$) when quantized to INT8 precision.

\section{State Buffer Layout and 10GB Memory Footprint}

While the neural network weights are globally shared across each archetype, individual agent instances require private, mutable execution state buffers to track financial positions, active orders, and historical metrics.

To eliminate heap fragmentation and garbage collection pauses, AMPS allocates a contiguous, data-oriented state buffer for all 1,000,000 agents in host DDR5 memory. Each individual agent instance is strictly constrained to an isolated state footprint of less than 10 Kilobytes ($<10\text{ KB}$):

\begin{equation}
    \text{Size}(\text{AgentState}) = \text{Portfolio} (64\text{ B}) + \text{OpenOrders} (256\text{ B}) + \text{LocalHistory} (512\text{ B}) + \text{PaddedBuffer} \le 10\text{ KB}
\end{equation}

Multiplying this per-agent buffer by 1,000,000 active instances yields a total system memory footprint of approximately 10.0 Gigabytes ($\sim 10.0\text{ GB}$) of DDR5 RAM. This allocation represents only 7.8\% of the 128GB physical memory available on the host workstation, leaving vast headroom for Zarr telemetry caches, `/dev/shm` shared memory rings, and the operating system kernel.

\section{Throughput Scaling via Asynchronous Event-Driven Poisson Queues}

A naive implementation of a 1,000,000-agent simulation would attempt to execute a neural policy forward pass for every single agent on every discrete microsecond tick. At a simulation clock of $100,000\text{ Ticks/Sec}$, synchronous evaluation would demand:

\begin{equation}
    1,000,000\text{ agents} \times 100,000\text{ ticks/sec} = 100,000,000,000\text{ (100 Billion) forward passes/sec}
\end{equation}

Divided across 12 Gracemont E-cores, each core would be required to compute $8.33\text{ Billion passes/sec}$ -- equivalent to one forward pass every $0.12\text{ nanoseconds}$, demanding over $1,000\text{ TFLOPS}$ of compute. This exceeds the physical compute capacity of the 12 Gracemont E-cores ($\sim 0.5\text{ TFLOPS}$) by three orders of magnitude.

To resolve this throughput paradox, AMPS implements an \textbf{Asynchronous Event-Driven Poisson Execution Queue}. In real-world financial markets, human traders and algorithmic trading systems do not re-quote on every single microsecond clock cycle. Instead, agent activation follows an asynchronous Poisson point process with state-dependent arrival intensity $\lambda_i(S_t, \Delta P_t)$:

\begin{equation}
    \lambda_i(S_t, \Delta P_t) = \lambda_{0, k} \cdot \left( 1 + \alpha_k |\text{OFI}_t| + \beta_k \frac{|\Delta P_t|}{\sigma_P} + \gamma_k (\text{Inventory}_{i, t})^2 \right)
\end{equation}

where $\lambda_{0, k}$ represents baseline quoting frequency for archetype $k$, and the scaling terms model heightened urgency during volatility jumps or inventory skew. 

At each microsecond tick ($\Delta t = 10\,\mu\text{s}$ at 100,000 TPS), only the subset of agents whose Poisson timers expire are enqueued for policy forward passes. Under standard and high-stress market regimes, the active evaluation batch size is bounded to:

\begin{equation}
    K_t \sim \text{Poisson}\left( \sum_{i=1}^N \lambda_i \Delta t \right) \in [1,000, \, 5,000]\text{ agents/tick}
\end{equation}

At a nominal Poisson arrival rate targeting $K_t \sim 1,000\text{ agents/tick}$, the total evaluation throughput required of the host CPU is:

\begin{equation}
    1,000\text{ agents/tick} \times 100,000\text{ ticks/sec} = 100,000,000\text{ forward passes/sec}
\end{equation}

Each student policy is structured as a compact 2-layer factorized MLP ($151 \to 128 \to 3$ discrete heads for action type, price offset, and volume tier), containing approximately $19,712$ parameters ($\approx 20\text{ KB}$ in INT8 per archetype). Executed via Intel VNNI (\texttt{\_mm256\_dpbusd\_epi32}) computing 32 INT8 MACs per cycle, evaluating 20K MACs requires approximately $625$ VNNI vector instructions ($\approx 150\text{ ns}$ single-pass). When tiled in SIMD groups of 4 agents per instruction stream across 12 Gracemont E-cores, effective evaluation latency drops to $\approx 40\text{ to }50\text{ ns}$ per agent. Each core processes $\approx 83$ passes per tick, consuming only $\approx 3.3\text{ to }4.2\,\mu\text{s}$ per $10\,\mu\text{s}$ tick ($\approx 35\text{-}42\%$ core utilization), comfortably satisfying hardware compute limits while preserving microsecond price-time priority determinism \cite{ohara1995market, cartea2015algorithmic}.

\section{Gracemont Silicon Topography \& L2 Cluster Cache Partitioning}

Executing batched student policy passes at sub-0.2 microsecond latency requires surgical hardware alignment with the physical cache topography of the Intel Core i7-14700K.

\subsection{Cluster-to-Archetype Pinning \& Active State Prefetching}

The 12 Gracemont Efficiency Cores of the i7-14700K are physically partitioned into \textbf{three 4-core clusters}, with each cluster sharing a dedicated \textbf{4MB Level 2 (L2) cache} (totaling 12MB L2 across all E-cores) \cite{intel2026gracemont}.

With student policy archetypes quantized to INT8 ($\approx 20\text{ KB}$ per archetype, $\approx 80\text{ KB}$ total across Market Makers, Institutional Whales, Momentum Scalpers, and Noise Traders), static weights consume less than $2\%$ of each cluster's 4MB L2 boundary. The three clusters are assigned static archetype affinities via Linux \texttt{sched\_setaffinity}:

\begin{itemize}
    \item \textbf{Cluster 0 (Cores 16-19):} Assigned to \textbf{Market Makers}. Pinned INT8 weights occupy $\approx 20\text{ KB}$, leaving $>3.9\text{ MB}$ of local L2 space for active LOB ladders and FIFO queues.
    \item \textbf{Cluster 1 (Cores 20-23):} Assigned to \textbf{Institutional Whales and Momentum Scalpers}. Combined weights occupy $\approx 40\text{ KB}$, leaving $>3.9\text{ MB}$ for state arrays.
    \item \textbf{Cluster 2 (Cores 24-27):} Assigned to \textbf{Noise Traders}. INT8 weights occupy $\approx 20\text{ KB}$, leaving $>3.9\text{ MB}$ for retail agent Poisson event buffers.
\end{itemize}

The complete $1,000,000$-agent state array ($151 \times \text{FP32} \approx 604\text{ MB}$) resides in 128GB system DDR5 RAM. To prevent DRAM fetch latency ($\approx 60\text{ to }70\text{ ns}$) from stalling execution, the active Poisson batch ($\approx 1,000\text{ agents} \approx 600\text{ KB}$) is prefetched via \texttt{\_mm\_prefetch} (\texttt{\_MM\_HINT\_T1}) 2 ticks ahead ($20\,\mu\text{s}$ lead time). This ensures zero L3 cache stalls during active execution.

\subsection{Vectorized In-Register SIMD Bit Expansion}

A critical component of the 151-dimensional state vector $S_t$ is the 128-bit Matryoshka SIRC narrative signature $B_t \in \mathbb{R}^{128}$ (Chapter \ref{ch:semantic_caching}). Stored compactly as two 64-bit unsigned integers (16 bytes), these bits are unpacked into 128 INT8 values ($+1$ for bit 1, $-1$ for bit 0) to feed the Intel VNNI matrix multiply pipeline.

Expanding 128 bits into 128 INT8 values requires exactly \textbf{four 256-bit YMM registers} ($4 \times 32\text{ bytes} = 128\text{ bytes}$). Out of the 16 YMM registers on AVX2, registers \texttt{YMM0} -- \texttt{YMM3} hold the active unpacked inputs, leaving 12 registers (\texttt{YMM4} -- \texttt{YMM15}) free for streaming INT8 weight matrices and VNNI accumulators (\texttt{\_mm256\_dpbusd\_epi32}), completely avoiding register spilling to the stack:

\begin{lstlisting}[language=C, caption={AVX2 In-Register Bit Expansion of 128-bit SIRC Signatures to INT8}]
#include <immintrin.h>

// Expands 32 packed bits into 32 INT8 values (+1 / -1) in one YMM register
__m256i expand_32bits_to_int8(uint32_t bits) {
    const __m256i pos_one = _mm256_set1_epi8(1);
    const __m256i neg_one = _mm256_set1_epi8(-1);
    
    // Broadcast 32-bit chunk across 8x 32-bit lanes
    __m256i bit_vec = _mm256_set1_epi32(bits);
    
    // Shift masks checking individual bit positions
    __m256i mask_shift = _mm256_set_epi32(
        0x80402010, 0x08040201, 0x80402010, 0x08040201,
        0x80402010, 0x08040201, 0x80402010, 0x08040201
    );
    __m256i tested = _mm256_and_si256(bit_vec, mask_shift);
    __m256i cmp_mask = _mm256_cmpeq_epi8(tested, mask_shift);
    
    // In-register blend: +1 if bit is 1, -1 if bit is 0
    return _mm256_blendv_epi8(neg_one, pos_one, cmp_mask);
}
\end{lstlisting}

This kernel unpacks all 128 bits directly into \texttt{YMM0} -- \texttt{YMM3} in under $8\text{ nanoseconds}$, zero-copy, with zero writes to host DRAM.
